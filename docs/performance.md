# fastsvm 0.1.0 性能評価

この文書は同梱の `benchmarks/results.json` から生成した表と、その解釈である。
**倍率 = sklearn の経過時間 / fastsvm の経過時間**。1 より大きい場合に fastsvm が速い。
全六ケースを掲載し、遅かったケースも除外していない。

## 学習・推論時間

| 課題 | 学習行数 × 特徴数 | fastsvm 学習 ms | sklearn 学習 ms | 学習倍率 | 推論倍率 |
|---|---:|---:|---:|---:|---:|
| 線形分類・dense | 3000 × 32 | 13.103 | 20.317 | 1.55× | 1.23× |
| 線形分類・CSR | 4500 × 1200 | 8.466 | 8.651 | 1.02× | 1.16× |
| RBF 二値分類 | 1800 × 16 | 17.242 | 18.602 | 1.08× | 3.50× |
| RBF 5クラス分類 | 1500 × 12 | 9.825 | 9.652 | 0.98× | 1.70× |
| RBF 回帰 | 1800 × 16 | 81.043 | 85.254 | 1.05× | 3.52× |
| 線形回帰 | 3000 × 32 | 10.020 | 9.189 | 0.92× | 0.96× |

| 課題 | 予測標本数 | fastsvm 推論 ms | sklearn 推論 ms | 推論倍率 |
|---|---:|---:|---:|---:|
| 線形分類・dense | 1000 | 0.122 | 0.150 | 1.23× |
| 線形分類・CSR | 1500 | 0.115 | 0.133 | 1.16× |
| RBF 二値分類 | 600 | 2.363 | 8.271 | 3.50× |
| RBF 5クラス分類 | 500 | 2.500 | 4.254 | 1.70× |
| RBF 回帰 | 600 | 4.548 | 15.995 | 3.52× |
| 線形回帰 | 1000 | 0.107 | 0.102 | 0.96× |

各値は 9 回の中央値。ウォームアップは両モデルで一回ずつ、計測は fastsvm→sklearn / sklearn→fastsvm の順序を交互に切り替えた。各回の生データ、25/75 パーセンタイル、ハイパーパラメーター、警告、最適化レポートは JSON に収録している。

## 数値と汎化指標

| 課題 | fastsvm score | sklearn score | 分類予測一致率 | 決定値・回帰予測の最大絶対差 |
|---|---:|---:|---:|---:|
| 線形分類・dense | 0.843000 | 0.843000 | 100.0% | 4.070e-06 |
| 線形分類・CSR | 0.867333 | 0.867333 | 100.0% | 1.457e-05 |
| RBF 二値分類 | 0.980000 | 0.980000 | 100.0% | 7.670e-05 |
| RBF 5クラス分類 | 0.986000 | 0.986000 | 100.0% | 3.856e-05 |
| RBF 回帰 | 0.946987 | 0.946987 | — | 5.159e-05 |
| 線形回帰 | 0.982209 | 0.982209 | — | 2.228e-05 |

分類の score は hold-out accuracy、回帰は hold-out R²。表示桁で一致しても配列が bit 単位で同一という意味ではない。
今回の全ケースで fastsvm は KKT 停止条件を満たし、両ライブラリの計測対象 fit から未収束警告は出ていない。
参照実装の収束は公開 API の警告と反復情報で確認しており、公開されない双対変数を使った独立な gap 証明は行っていない。

## 環境

| 項目 | 値 |
|---|---|
| Python | 3.13.5 |
| NumPy / SciPy | 2.3.5 / 1.17.0 |
| scikit-learn | 1.8.0 |
| Cython / GCC | 3.2.4 / 14.2.0 |
| OS | Linux x86_64、glibc 2.41 |
| CPU の表示文字列 | AMD EPYC 9V74 80-Core Processor |
| コンテナから見える論理 CPU 数 | 5 |
| fastsvm ビルド | `FASTSVM_NATIVE=1 FASTSVM_OPENMP=1` |
| 実測スレッド数 | **1**。BLAS / OpenMP / n_jobs とも一スレッド |
| データ乱数 seed | 20261006。各生成器の個別 seed はスクリプト参照 |

CPU の表示文字列はホスト由来であり、80 コアを占有して測定したという意味ではない。コンテナの共有環境であり、CPU pinning・負荷分離・複数マシンでの反復はしていない。

fastsvm はローカル CPU 向けにコンパイルし、比較対象はこの環境にインストール済みの sklearn バイナリを使用した。LIBSVM/LIBLINEAR を同一コンパイラフラグで再ビルドした比較ではない。したがって倍率を「アルゴリズムだけの効果」と解釈しない。

## 計測対象と公平性の範囲

データ生成と StandardScaler / 行正規化は計測外。標準化の統計は train 分割から学習し、test に適用する。計測する fit には、入力検証、必要なコピー、ソルバー、fastsvm の通常の最適化診断を含める。predict は一バッチの全所要時間で、入力検証を含む。

`C`、損失、gamma、epsilon、切片、cache_size、名目 tol を対応させた。全ケースで tol は 1e-4。線形参照実装は `dual=True` に固定し、別の primal 算法と無自覚に比較しない。
ただし同じ tol でも停止規則の定義・作業集合選択・反復の単位は同一ではない。両実装を完全に同じ certified gap まで回した比較ではない。

今回の問題は合成データであり、全ての実データ・超大規模・極端な条件数を代表しない。1.02×、0.98× など 1 に近い差を統計的な勝利と断定しない。個別最適化を一つずつ無効化する統制された ablation も未実施なので、「手動アンロールだけで 3.5 倍」などの因果的な主張はしない。

線形回帰の学習・推論と、多クラス RBF の学習では今回 fastsvm が遅かった。したがって「常に sklearn より速い」「世界最速」とは結論しない。RBF 二値分類・回帰の推論については、この条件で約 3.5 倍の短縮を観測した。

## メモリと並列化

実行プロセス全体の peak RSS は測定していない。JSON の `cache_bytes` は行キャッシュの確保量で、RSS でも総メモリでもない。小さな n ではキャッシュ容量が n 行に達することがある。

OpenMP 対応ビルドでの逐次/並列予測の一致はテストしたが、複数スレッドの speedup / scalability は本レポートでは測定していない。SMO の逐次依存する二変数更新自体を並列化しているわけではない。

## 再現方法

GitHub ソース ZIP を新しいディレクトリに展開してから、次を実行する。

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
FASTSVM_NATIVE=1 FASTSVM_OPENMP=1 python -m pip install '.[dev]'
FASTSVM_NATIVE=1 FASTSVM_OPENMP=1 \
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
python benchmarks/benchmark.py --repeat 9 --output benchmarks/my_results.json
```

同じバージョンの実験環境を作るときは `docs/validation-requirements.txt` も参照する。コンパイラ・CPU・OS を変えると結果は変わる。既にビルドしたツリーでフラグを変更するときは、`build/` と生成された `_core.c` を消して再ビルドする。
